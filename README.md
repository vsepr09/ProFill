# ProFill

하루 단백질 목표를 정하고, 먹을 때마다 체크해서 채우는 헬스인용 단백질 트래커예요.

**사이트 바로가기: https://vsepr09.github.io/ProFill/**

인천과학예술영재학교 학생들이 함께 쓰려고 만들었어요. 학교 급식의 단백질 정보를 매일 자동으로 받아와서, 급식과 따로 챙겨 먹는 보충제를 한 화면에서 관리할 수 있어요.

## 이런 문제를 풀어요

운동하는 사람은 하루 단백질을 얼마나 먹어야 하는지는 대충 알아도, 오늘 실제로 얼마나 먹었는지, 남은 양을 언제 무엇으로 채울지는 매번 계산하기 번거로워요. 기숙사 생활을 하면 급식이 식사의 대부분인데, 급식 단백질도 따로 찾아봐야 하고, 저녁 이후에는 기기를 쓸 수 없어 기록이 끊기기 쉬워요.

ProFill은 이걸 세 단계로 줄여요.

1. 오늘 먹을 식품(급식 포함)을 체크리스트에 담으면, 언제 무엇을 먹을지 시간대별로 추천해 줘요.
2. 먹을 때마다 동그라미를 눌러 체크해요.
3. 화면 맨 위 bar가 채워지고, 목표를 채운 날이 이어지면 파란 불꽃 숫자가 올라가요.

## 주요 기능

### 하루 목표와 bar
- 몸무게와 목표(유지 1.4g, 근육 증가 1.6g, 체지방 감량 2.2g, 또는 직접 입력)를 고르면 하루 목표가 정해져요.
- bar에는 먹은 단백질이 식품별 색깔 칸으로 쌓이고, 체크리스트를 다 먹었을 때의 예상량과 목표선이 함께 보여요.
- 목표를 연속으로 채운 날 수가 파란 불꽃으로, 최근 7일 달성률이 막대로 보여요.

### 오늘의 추천
- 체크리스트를 아침(08:00), 점심(12:40), 저녁(18:20), 자기 전(23:00)에 나눠 배치하고, 끼니 간격이 5시간 넘게 벌어지면 간식 시간을 넣어요.
- 운동 시간(시작과 끝)을 하루 여러 번 넣을 수 있고, 운동 직후에는 빨리 흡수되는 단백질을, 자기 전에는 천천히 흡수되는 단백질을 먼저 배치해요.
- 계획대로 먹어도 목표가 부족하면, 무엇을 몇 개 더 담으면 되는지 버튼으로 알려 줘요.

### 저녁에 기기를 못 쓸 때
- 오후 4시부터 **오늘 밤 먹을 것** 칸이 떠요. 저녁 급식과 기기 사용 마감 시간(기본 18:20) 이후에 먹을 것을 보여 주고, 한 번에 미리 체크할 수 있어요.
- 다음 날 낮 12시까지는 **어제 기록 마무리하기** 칸에서 실제로 먹은 것만 고칠 수 있어요. 연속 기록과 달력도 같이 고쳐져요.

### 급식
- 나이스(NEIS)에서 아침, 점심, 저녁 메뉴와 단백질 g수를 매일 받아와요. 오늘과 내일 급식을 볼 수 있어요.
- 버튼 한 번으로 체크리스트에 담고, 0.5인분부터 2인분까지 먹은 양을 조절할 수 있어요.

### 식품 목록과 체크리스트
- 식품은 각자 직접 추가해요. 이름, 단백질 g수, 1회 양, 흡수 속도를 적어요.
- 내가 먹는 보충제나 간식은 이름과 단백질 g수를 적어 직접 추가할 수 있어요.
- 최근 일주일 동안 자주 담은 식품이 목록 맨 위로 올라와요.
- 자주 먹는 조합은 루틴으로 저장하고, 자정이 지나면 루틴이나 전날 목록으로 자동으로 채울 수 있어요.

### 운동 기록과 나의 운동법
- 매일 운동한 부위(가슴, 등, 어깨, 하체, 삼두, 이두, 복근, 전완)를 눌러 체크해요. 부위마다 마지막으로 운동한 날이 "어제", "3일 전"처럼 보이고, 7일 넘게 안 한 부위는 주황색으로 표시돼요.
- **나의 운동법**에서 몇 분할로 할지, 분할마다 운동할 부위와 운동(이름, 무게 또는 맨몸, 개수, 세트 수), 요일마다 몇 일차를 할지 정해요. 운동법이 있으면 운동 칸에는 운동법에 들어 있는 부위만 보이고, 그날 할 운동이 함께 나와요.
- 저녁에 기기를 못 써서 체크하지 못했으면, 다음 날 아침 **어제 기록 마무리하기**에서 어제 운동한 부위를 고칠 수 있어요.

### 기록
- 최근 7일 막대를 누르면 기록 달력이 열려요. 날짜별 달성률, 그날 먹은 식품, 운동한 부위를 볼 수 있고, 운동한 날에는 작은 점이 찍혀요.
- 월요일에는 **지난주 리포트**(하루 평균, 달성 일수, 가장 부족한 요일, 많이 먹은 식품, 나의 운동법 기준으로 계획한 날 중 운동한 날과 빠뜨린 부위)가 떠요.

### 친구
- 달성률을 공개한 친구끼리 bar 아래 **오늘 친구들**에서 순위를 볼 수 있어요. 필요 없으면 설정에서 이 칸을 끌 수 있어요. **오늘의 추천**도 설정에서 끌 수 있어요.
- **자세한 정보 공개**를 켠 친구는 오늘 먹은 식품, 오늘 운동한 부위, 나의 운동법, 최근 7일 기록, 몸무게와 목표까지 볼 수 있어요. 두 가지 모두 설정에서 끄고 켤 수 있고, 처음에는 꺼져 있어요.

### 그 밖에
- 처음 가입하면 세 단계 사용법이 나오고, 설정에서 다시 볼 수 있어요.
- 확인창 없이 바로 동작하고, 지운 것은 5초 안에 '되돌리기'로 복구할 수 있어요.
- 한 번 열었던 사이트는 인터넷 없이도 열리고, 그동안 체크한 건 연결되면 자동으로 저장돼요.
- 아이패드와 다른 기기에서 같은 계정을 쓰면 바뀐 내용이 실시간으로 반영돼요.
- 라이트/다크 모드, 홈 화면에 추가해서 앱처럼 쓰기, 비밀번호 바꾸기, 계정 삭제를 지원해요.

## 목표 숫자의 근거

| 목표 | 체중 1kg당 | 근거 |
|---|---|---|
| 유지 | 1.4g | 운동하는 사람 대부분은 하루 1.4–2.0g/kg이면 충분 (ISSN, 2017) |
| 근육 증가 | 1.6g | 약 1.6g/kg을 넘기면 근육 증가 효과가 더 커지지 않음 (Morton 외, 2018) |
| 체지방 감량 | 2.2g | 감량 중에는 제지방 1kg당 2.3–3.1g 권장 (Helms 외, 2014), 이를 체중 기준으로 환산 |
| 직접 입력 | 0.8–3.5g | 위 근거를 참고해 직접 정함 |

시간대별 추천은 "한 번에 20–40g씩, 3–4시간 간격으로 고르게"라는 ISSN 권고를 따라요.

- [ISSN Position Stand: protein and exercise (2017)](https://pmc.ncbi.nlm.nih.gov/articles/PMC5477153/)
- [Morton 외, British Journal of Sports Medicine (2018)](https://pubmed.ncbi.nlm.nih.gov/28698222/)
- [Helms 외, IJSNEM (2014)](https://pubmed.ncbi.nlm.nih.gov/24092765/)

연구는 대부분 성인을 대상으로 했어요. 건강 문제가 있다면 먼저 전문가와 상의해 주세요.

## 어떻게 만들어졌나요

서버 없이 무료 서비스만으로 운영돼요.

| 역할 | 사용한 것 |
|---|---|
| 화면 | HTML, CSS, JavaScript (프레임워크 없음) |
| 사이트 호스팅 | GitHub Pages |
| 계정, 기록 저장 | Firebase Authentication, Cloud Firestore |
| 급식 정보 | 나이스 교육정보 개방 포털 API |
| 자동 갱신 | GitHub Actions (매일 00:05, 06:00 한국 시간) |
| 인터넷 없이 열기 | 서비스 워커, Firestore 오프라인 저장 |

GitHub Actions가 매일 나이스에서 지난 7일부터 앞으로 10일까지의 급식을 받아 `data/meals.json`을 만들고, 사이트와 함께 GitHub Pages에 배포해요. 그래서 급식 파일은 저장소에는 보이지 않아요.

### 파일 구성

| 파일 | 내용 |
|---|---|
| `index.html` | 페이지 뼈대 |
| `app.js` | 화면 그리기, 추천 계산, 로그인과 저장, 친구 기능 |
| `style.css` | 디자인 (라이트/다크 테마 포함) |
| `data.js` | 목표별 숫자 |
| `firebase-config.js` | Firebase 프로젝트 연결 정보 |
| `sw.js` | 인터넷 없이 열기 위한 서비스 워커 |
| `manifest.webmanifest`, `icon-*.png`, `apple-touch-icon.png` | 홈 화면 앱 정보와 아이콘 |
| `fetch_meals.py` | 나이스에서 급식 정보를 받는 스크립트 |
| `firestore.rules` | 데이터 보안 규칙 |
| `.github/workflows/deploy.yml` | 급식 받기와 사이트 배포 자동화 |

### 저장되는 데이터

| Firestore 위치 | 내용 | 누가 볼 수 있나 |
|---|---|---|
| `users/{uid}` | 내 설정, 체크리스트, 루틴, 기록, 운동 부위, 나의 운동법 | 나만 |
| `public/{uid}` | 닉네임, 오늘 달성률, 연속 기록 (자세한 정보 공개 시 먹은 식품, 운동 부위, 운동법, 최근 7일, 몸무게, 목표) | 로그인한 사용자 (공개를 켠 경우에만 만들어짐) |

### 보안과 개인정보

- 로그인은 아이디와 비밀번호로만 해요. 이메일이나 실명은 받지 않아요.
- 친구 공개는 기본으로 꺼져 있고, 켠 사람만 공개돼요. 끄면 공개 정보가 바로 지워져요.
- 설정의 **계정 삭제**를 누르면 기록, 공개 정보, 로그인 정보가 모두 지워져요.
- `firebase-config.js`의 `apiKey`는 Firebase 웹 앱에서 원래 공개되는 값이에요. 비밀번호가 아니라 프로젝트를 구분하는 용도예요.

## 우리 학교용으로 직접 만들어 보기

다른 학교에서 쓰고 싶다면 이 저장소를 Fork해서 직접 배포할 수 있어요.

1. **Fork**: 이 저장소를 내 계정으로 Fork해요.
2. **Firebase**
   - console.firebase.google.com에서 프로젝트를 만들어요.
   - Authentication에서 '이메일/비밀번호' 로그인을 켜요.
   - **Firestore Database**를 만들고(위치: 서울), 규칙 탭에 `firestore.rules` 내용을 붙여 넣어 게시해요. Realtime Database가 아니라 Firestore여야 해요.
   - 프로젝트 설정에서 웹 앱을 등록하고, 나온 값을 `firebase-config.js`에 붙여 넣어요.
   - Authentication > 설정 > 승인된 도메인에 `내아이디.github.io`를 추가해요.
3. **나이스 인증키**
   - open.neis.go.kr에서 인증키를 발급받아요.
   - 저장소 Settings > Secrets and variables > Actions에 `NEIS_KEY`라는 이름으로 넣어요.
4. **학교에 맞추기**
   - `fetch_meals.py` 위쪽의 `SCHOOL_NAME`(학교 이름)과 `ATPT_CODE`(시도교육청 코드)를 바꿔요.
   - 급식 시간은 `app.js`의 `buildPlan` 함수에서, 기기 사용 마감 시간 기본값은 `freshData` 함수에서 바꿀 수 있어요. 마감 시간은 각자 설정에서도 바꿀 수 있어요.
5. **배포**: Settings > Pages > Source를 'GitHub Actions'로 바꾸고, Actions 탭에서 워크플로를 한 번 실행해요.

### 알아 두기

- 비밀번호를 잊으면 되찾을 수 없어요. 관리자가 Firebase 콘솔에서 계정을 지운 뒤 다시 가입해야 해요. 기억하고 있다면 설정에서 직접 바꿀 수 있어요.
- 테스트 계정은 Firebase 콘솔이 아니라 그 계정으로 로그인해서 설정의 **계정 삭제**로 지워야 기록까지 깔끔하게 지워져요.
- 저장소에 60일 동안 변화가 없으면 GitHub가 예약 실행을 멈춰요. Actions 탭에서 다시 켜 주세요.
- 주말, 방학처럼 학교가 급식 정보를 올리지 않은 날에는 급식이 표시되지 않아요.
